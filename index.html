Q2. Block Diagram Flow

  1. The input unit sends data and instructions to memory.
  2. The control unit (CU) fetches an instruction from memory, decodes it, and sends control signals to the ALU, memory and I/O.
  3. The ALU processes the data, and the result goes back to memory.
  4. The output unit receives the result via the I/O interface.
  • Data: flows between I/O, memory and ALU.
  • Instructions: flow from memory to the CU.
  • Control signals: flow from the CU to all units.

Q3. Campus Automation with Scanners and Card Readers

Attendance

Students tap RFID/smart ID cards on a reader at the classroom door. The reader logs the ID and timestamp to the database. OMR sheets can be used for exam attendance.

Library checkout

The barcode scanner reads the book's code and the card reader reads the student ID. The system records the issue automatically, sets the due date, and flags overdue books or unissued books at the gate.

Q6. Plotter vs UHD Monitor + Large-format Printer

Verdict: The monitor + large-format printer combination is better for most blueprint work.

  • Line resolution: Plotters give crisp vector lines, but modern printers at 1200+ dpi match them.
  • Scalability: Printers handle any size, colour and raster/vector mix. Plotters are slower and more limited.
  • Long-term cost: Printers have higher ink costs but are faster and more versatile. Plotters have cheap pens but low throughput and rising maintenance.

Q7. Facial vs Voice Recognition (Noisy, Public Setting)

Facial recognition

Unaffected by noise. Weaknesses are lighting, masks and angle, and spoofing via photos, videos or deepfakes unless liveness detection is used. It also raises privacy concerns.

Voice recognition

Noise sharply reduces accuracy. It is open to replay and synthetic-voice attacks and can be overheard in public.

Verdict: Face recognition with liveness detection is more reliable here. Pairing it with a PIN or card (multi-factor) is best.

Q8. Hands-free Workstation for a Visually Impaired User

Input

  • Headset microphone for voice recognition (dictation and commands)
  • Braille or tactile-marked keyboard
  • Scanner with OCR (optional)

Output

  • Screen reader (NVDA/JAWS) linked to a speech synthesizer for voice response
  • Refreshable Braille display
  • Audio feedback through headphones

Integration

The user speaks or types, the system processes it, and the screen reader reads results aloud. Braille output backs up speech for exact text and noisy settings.
